# 饭友圈精简 PRD 讨论稿

状态：**待讨论、未批准、未开发**。日期：2026-11-17，基于 1.6.3。以下为建议，不代表已确认需求；保留现有原色和离线做饭功能。

## 目标与演示闭环

用户分享自己的菜谱，下载别人的菜谱到本机跟做，换设备时恢复个人配置。

建议演示：A 发布带图和用量的菜 → B 浏览并评论 → 下载后断网跟做 → 在另一设备登录恢复配置。

## 建议首版范围

| 功能 | 建议行为 |
| --- | --- |
| 账号 | 用户名／密码注册登录退出；浏览可免登录，发布、评论、备份需登录 |
| 发布菜谱 | 本地草稿；名称、成品图、份数、食材用量、步骤；有依据才填火力／状态；作者编辑或删除自己的内容 |
| 饭友圈 | 菜谱列表、搜索和详情；不做独立动态流、私信、关注或推荐算法 |
| 讨论 | 菜谱下评论与单层回复；只能管理自己的评论，管理员可移除不合适内容 |
| 下载 | “下载到我的菜谱”保存特定版本与图片，断网可跟做；收藏与下载分开 |
| 配置备份 | 手动备份／恢复，显示更新时间、范围与覆盖确认；失败保留有效本机数据 |

## 关键规则

- 内置 200 道和用户菜谱分开标识；后者注明作者和“用户分享，未经项目核对”，不冒充多信源验收。支持原创／来源说明。
- 菜谱有独立 ID、作者、版本。作者修改不静默改动已下载步骤；正在跟做时不替换版本。
- 建议作者删除后停止公开展示／新下载，已有下载副本保留版本和来源；此规则待确认。
- 建议备份食材、常备调料、常用顺序、收藏、偏好；当前一餐、计时器和临时页面状态不跨设备同步。
- 首次登录不自动覆盖匿名本机数据；恢复经确认。退出或换账号不能把 A 配置上传给 B。账号空间和匿名数据如何切换需在界面方案中明确。
- 首版不做自动冲突合并。失败时保留草稿、评论输入；下载失败不能留下可开做的半份菜谱，重复操作不得创建重复副本。
- 用户菜谱完成下载后才进入本地推荐／跟做。未识别食材如实标记；过敏原无法可靠识别时，不能宣称“安全可做”，默认不进入自动安全推荐，保留原配料供核查。

## 候选部署

保留 React + Capacitor，增加 Node.js 后端、SQLite 与专用图片目录。手机访问后端而非直接访问数据库。另一台电脑可承担临时服务，HTTPS 穿透为候选；地址可配置，切换服务器不能把旧凭证发送给新服务。

演示前确认电脑保持开机、教室网络可达、重启后数据仍在。服务中断要显示失败与重试，原内置菜谱和已完成下载继续可用。上述技术是建议，尚未锁定供应商。

## 最低验收

1. 两账号不能修改彼此内容或读取私有配置；后端鉴权，密码安全哈希，上传限制类型与体积。
2. A 发布后 B 从服务真实读取；不以硬编码假社区冒充联网。修改后版本可区分。
3. 下载包含图片、用量、步骤；断网可跟做，服务关闭不影响原离线功能。
4. 备份与恢复有时间、范围、确认；断网不覆盖有效数据，换账号不串数据。
5. 现有 200 道、菜篮、前台响铃、悬浮长按隐藏和安卓返回通过回归。
6. 演示手机和实际课堂网络跑通闭环，后台／锁屏仍按未实现说明。
