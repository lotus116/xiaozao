# 执行计划

依据：docs/PRD.md；确认日期：2026-11-05。

## 本轮目标

自主完成手机 Web App 的手动输入 → 菜谱推荐 → 菜谱详情/备料 → 分步跟做完整流程，随后完成搜索、收藏、本地保存和轻量营养参考，调试验证并用本地 Git 保存可运行版本。拍照识别本轮不做。

用户明确要求在新会话使用 gpt-6-astra、high 推理强度，设置目标、持续执行到完成，debug 后 Git 管理版本并汇报。无需为常规实现选择重复询问。

## 自动执行流程

1. 阅读 PRD、此计划和适用的项目指令；建立可验收的执行目标（create_goal），不擅自设置 token 预算。
2. 检查现有文件和 Git 状态。项目初始为空；如没有仓库则初始化本地 Git。保护现有用户修改，不提交密钥、缓存或构建产物。
3. 选择适合轻量手机 Web App 的技术栈，记录必要决策。使用适用的设计/实现技能；页面风格统一、中文清晰、触屏易用。
4. 按下列阶段实现，更新本文件勾选状态，必要时在文末记录实测证据与阻塞。
5. 完成有意义的规则测试、构建、浏览器流程验证；修复失败后重测受影响部分。
6. 本地 Git 分阶段提交，最终报告分支、提交、运行方法、验证结果和真实限制。不自动推送远端，不上架商店。
7. 所有本轮验收完成后标记目标完成，并向用户汇报；若客观阻塞则报告证据，不虚报通过。

## 阶段及交付

- [x] 阶段 1：数据样板与工程基础。8–10 道可信菜谱起步，食材别名、必需/可选配料、份数、营养和来源结构完整；至少 5 组匹配用例，含齐全、缺料、无匹配。
- [x] 阶段 2：核心流程。手动添加/删除食材、调料选择、匹配分组、菜谱搜索和详情；无需 AI 可完整走通。
- [x] 阶段 3：新手体验。备料勾选、分步操作、计时器、收藏、本地保存和有依据的营养参考；刷新数据保留。
- [ ] 阶段 4：完善与调试。内容向约 30 道扩充；逐项核对来源和步骤，不以数量为理由降低真实性。手机布局、异常状态、规则测试、构建和浏览器演示均检查。
- [ ] 阶段 5：版本交付。README 运行说明、测试结果、Git 提交、完成报告。提供可访问的本地预览方法；公开托管另行按实际授权处理，不阻塞本地交付。

## 测试重点

- 匹配：别名归一化、去重、缺少调料、可选配料缺失、0/1/2/>2 样缺料、空输入、稳定排序。
- 流程：添加 → 推荐 → 详情 → 备料 → 步骤前后切换 → 计时 → 完成。
- 保存：刷新后食材及收藏保留，损坏存储有合理降级。
- 计时：按时间戳计算，切换步骤与刷新后的行为明确，避免重复或负计时。
- 内容：来源链接、份数/单位一致、营养未知不填假数值。
- 页面：手机宽度无横向溢出，搜索和无结果可恢复，键盘操作和按钮标签可用。
