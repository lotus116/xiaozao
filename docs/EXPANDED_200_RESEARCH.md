## 范围与保留

在原有 99 道、302 步基础上新增 101 道、323 步，共 **200 道、625 步**。旧菜 ID、步骤顺序、计时和已保存进度保持兼容。新增菜包含牛排、黑椒牛柳、红烧肉、卤肉饭等家常菜，以及意面、咖喱、日式丼饭、泰式炒粉、地中海沙拉和常见汤品；按家庭可采购食材简化，不声称每种地方做法都只有这一种标准。

每道新增菜具备量化原料、分步用量、火力、可观察状态、备料工具、补救说明、来源与离线照片。总用时、份数及部分简化后的用量属于编辑估计；不编造营养数字、热门排名、真实用户评分或试做经历。全部新增菜尚未由本项目实际下厨验证。

- 60 道以 HowToCook 菜谱为主要资料，固定提交版本 `25854882a423d7dbd6f6146b6554e2fa3b8f9804`；41 道以 TheMealDB 官方 API 的完整用料和步骤为主要资料，不仅凭照片或菜名编写。
- 读取 31 篇补充技法／菜谱资料。23 道另外记录独立的同菜参考（下表标记“同菜参考”）；其余使用明确范围的技法对照。主配方、技法与安全指引分别归因，不能把通用技法当作另一份完整相同配方。
- API 中原来源的访问状态：retrieved 28 篇；unavailable-or-unrelated 13 篇。不可读页面不冒称重新核读；可读原来源仍可能是 API 的上游，不能因此算作独立印证。
- [核对台账](../scripts/catalog/research.json)保存原链接、访问日期、固定版本与读取内容 SHA-256；[编辑稿](../scripts/catalog/expanded-recipes.txt)保存实际改写后的用量／动作／状态。运行 `node scripts/catalog/build-expanded.mjs` 生成应用数据，不在用户设备联网取配方。
- 安全终点另依 [FoodSafety.gov 中心温度表](https://www.foodsafety.gov/food-safety-charts/safe-minimum-internal-temperatures)与[四步食品处理指引](https://www.foodsafety.gov/keep-food-safe/4-steps-to-food-safety)核对。计时只提示检查，不代替熟度判断；不沿用冲洗生鸡肉、以表面上色保证肉熟或干豆直接套用罐头豆短时加热等做法。

## 具体修正

牛排保留完整肉块、明确厚度、分段火力、黄油后放和静置；库存的牛肉末不冒充牛排。煎炸鸡与猪排写明中心检查，炸制补救禁止向热油加水。松饼纠正 API 薄饼与厚松饼照片不一致的问题；酥皮培根鸡蛋明确为简化变体；银耳莲子羹不冒称含米的粥。番茄罐头、成品意面酱和甜番茄沙司不互相直接替换。需要预煮面、熟豆、熟饭或已熟香肠的菜写明其状态。

同一道菜的不同来源常有调味、油量或烹调工具差异，因此小灶展示采用点与取舍，而不是混合所有步骤。成品图片是来源作者参考；配料、摆盘、大小和颜色与本版可不同，不作为本项目试做证据。

## 交互与验收

悬浮计时器恢复点击／拖动／长按隐藏／设置恢复；隐藏不终止计时。搜索支持牛排／牛扒及中英文别名，关键词默认跨分类，之后允许主动筛选；结果优先展示菜名命中而非仅可选肉末命中。菜单保存上限随实际菜数增长，食材保存容量从 200 扩到 500 项；扩充后的 233 种食材全部归组。新增食材进入过敏提示，区分蟹味菇与甲壳类、椰奶与奶制品，成品酱料提示核对包装。

[逐菜验收页](CATALOG_REVIEW.html)可直接本地打开。[测试记录](TEST_REPORT.md)记录自动检查和手机模拟的实际结果。既有菜篮顺序依据仍只覆盖已核对的 25 道，其余保留相对顺序，不凭扩库自动编造先后安排。真实安卓安装、系统返回、输入法、后台／锁屏提示及真实下厨仍不能用浏览器自动化代替。
