# 菜篮顺序建议

2026-11-06。本功能只做逐道顺序建议，不做多锅或跨菜步骤穿插，不调用 AI 服务，也不修改进行中的一餐。

## 交互与状态

- 菜篮点「帮我排个顺序」先打开内嵌预览，展示开火前准备、逐菜顺序、可展开的理由和对应菜谱步骤。
- 只有「采用这个顺序」才更新菜篮；「先不采用」、看菜谱、浏览器返回/前进、刷新都不会隐式采用。
- 采用后可以「撤销采用」或使用原有「提前 / 延后」。新增、移除或手调菜篮后，旧预览必须重新生成，旧撤销不能覆盖较新的调整或复活移除的菜。
- 正在做的一餐保留原 `meal.ids`、`done`、当前步骤、计时、收藏、食材和偏好。新的顺序只影响下次从菜篮开始的一餐。
- 不增加必做勾选、账户或持久化字段；采用后的顺序由原有菜篮存储保存。预览和撤销仅限本次页面，刷新后不保留。
- 过敏或隐藏忌口造成禁用时，不生成或采用建议；移出受限菜后恢复。

## 建议依据

`src/meal-planning-data.js` 是独立人工编辑元数据，按稳定 recipe ID 指向现有步骤。没有基于菜名、分类、厨具或分钟数批量猜标签。

每条排序依据包含 `order`（first/normal/last）、针对这道菜的 `reason` 和 `evidence`（步骤编号、标题、原句片段）。准备提醒单独包含 `kind`、`text` 和同样的步骤证据。

规划器逐项核对最新步骤的标题、原句。缺失、失配或无依据时，不展示失效标签与准备提醒；排序回退到保持未分类菜的相对顺序。同优先级稳定排序，不做自动用时排序。准备提醒不影响排序。

最终明确排序范围是 10 道：三道电饭锅菜、玉米排骨汤、南瓜粥，以及明确要求临吃再拌、趁热吃或避免面条吸汤的拍黄瓜、凉拌木耳、番茄蛋花汤面、清炒绿豆芽、凉拌豆腐皮。另有 19 条准备提醒，两者去重共 25 道元数据。其他菜可以参与预览，但没有依据的不会被硬排成“先做/最后做”。这不是声称 99 道均已有细分排程标签。全部元数据已与最终 99 道教学正文逐条重新绑定。

## 提前准备与估时

- 提醒覆盖冷藏腌制、按包装泡发、完整前置备料后启动电饭锅，以及熟米饭前置条件。
- 肉类腌制放冷藏，木耳等按包装处理，不用久泡/变质原料。电饭锅提醒包含必要的前置炒料/加水，不暗示跳过前置步骤直接按开关；带肉焖饭核对本机说明并立即开始，不常温预约。
- 提醒不会启动计时、标记步骤完成或改变跟做进度。已经完成的准备由用户在整页跟做里跳过，不重复操作。
- 展示“菜谱标注合计约 X 分钟”，仅将 `recipe.minutes` 每道加一次，再向上取整至 5 分钟；不累加步骤计时、腌制或电饭锅等待，不凭空扣掉可能重叠的时间。
- 这是逐道做的粗略参考，不是整餐上桌倒计时，不承诺排序节省时间。明确提示未计入的泡发、另煮米饭、加量、火力、熟练度和机器程序可能需要额外时间。缺任何一道用时就明确标出，不把部分合计当完整整餐。
