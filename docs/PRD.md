# 做饭新手助手 — PRD v1.1

确认日期：2026-11-05（Asia/Hong_Kong）
状态：已完成首版与本轮六项反馈的本地迭代。开发者：用户与 Codex。

## 1. 产品目标

面向有做饭条件、经验不足的新手，回答“冰箱里有这些东西，现在能做什么？”，并帮助用户完成烹饪。首发手机 Web App，预留通过 Capacitor 打包 Android / iOS 的路径。

核心流程：手动添加食材 → 查看推荐 → 选择菜谱 → 确认用量与备料 → 分步跟做。

课程要求：能够向别人现场演示。无需首发上架应用商店。当前优先完成真实可用的核心流程，拍照识别后续再做。

## 2. 用户与内容定位

- 中文界面，中式家常菜为主，以 1–2 人份、10–30 分钟、常见厨具的菜谱为优先。
- 首批 27 道基础上增加国内中文资源，当前 53 道；新增以多样化家常菜为主。
- 围绕鸡蛋、番茄、土豆、豆腐、鸡肉及常见蔬菜形成有效的组合覆盖。
- 每道菜注明标准份数、用量、厨具、难度、时间、步骤及来源。
- 网络来源必须可追溯，核对作者、步骤、用量、试做依据和内容/图片使用条件。不能把公开可访问直接视为可任意转载。
- 区分“原作者称经过试做”“有可核实的读者反馈”“本项目实际试做”。不得虚构验证状态。
- 来源参考候选：Good Food https://www.bbcgoodfood.com/bbc-good-food-app-faq 。具体选菜和可用性仍须逐项核实，不限定必须使用该站。

## 3. 第一版功能

| 功能 | 行为与边界 |
| --- | --- |
| 手动添加食材 | 搜索名称、常用食材快捷选择、删除；支持番茄/西红柿等别名；重复添加去重 |
| 常备调料 | 明确勾选后长期保存；清空本次食材不删除调料，不默认油盐酱醋全部具备 |
| 分类 | 菜肴、主食、汤羹分开推荐、搜索与收藏浏览 |
| 厨房设置 | 常见过敏严格排除，包含可选原料与已知复合调味品；普通忌口可隐藏或提醒 |
| 推荐 | 分开显示食材种类齐全、再添 1–2 样；列出全部必需缺料及匹配理由 |
| 搜索 | 按菜名或食材查找内置菜谱，提供简单的时长和难度筛选 |
| 菜谱详情 | 标准用量、份数、厨具、时间、清晰步骤、营养参考和可访问的来源链接 |
| 分步跟做 | 备料勾选、上一步/下一步；步骤计时及独立悬浮计时器，支持暂停、继续、加一分钟 |
| 营养参考 | 每份热量、蛋白质、碳水、脂肪；注明标准份量、估算及数据依据 |
| 本地保存 | 免登录，保存当前设备食材清单和收藏，刷新后保留 |

## 4. 推荐与营养规则

1. 必需食材和必需调料均参与匹配；可选配料缺少不阻止匹配。
2. 先展示种类齐全的菜，再展示缺少 1–2 样的菜。同组优先简单、耗时短的菜，排序稳定且可解释。
3. 不记录库存重量，因此“食材种类齐全”不代表用量足够；在详情/备料阶段提醒确认标准用量。
4. 无合适结果时解释原因，提供修改食材或搜索菜谱入口，不编造结果。
5. 营养按标准菜谱及其份数计算，不根据照片猜测重量。资料缺失显示“暂无估算”，不得编造数字。
6. 搭配提醒采用简单、可解释的规则，例如缺少蔬菜时提示搭配蔬菜，不做个人健康评分或医学建议。
7. 新手步骤应包含来源支持的火力、时间、可观察状态；不凭空补写关键烹饪参数。内容不足时换用更明确的来源。

## 5. 拍照辅助：后续范围，本轮不实现

流程：拍照/选图 → 识别候选 → 用户增删修改 → 确认添加。

- 所有结果确认后才进入清单；失败、超时、拒绝权限都不阻塞手动输入。
- 不估计重量、保质期或新鲜度，不承诺识别不透明包装或完全遮挡食材。
- YOLO、自部署模型、浏览器 ONNX 或第三方视觉服务均为候选，尚未选定。
- 之后用真实的裸露、袋装、遮挡及包装照片测试效果、耗时和纠错成本，再决定接入方式。
- 第一版不添加假识别按钮或假结果。

## 6. 暂不实现

账号和云同步、社区发布、自动爬取、实时生成菜谱、精确库存扣减、保质期管理、个性化减重计划、包装文字识别、原生应用打包。

## 7. 实现原则

- 手机优先；数据、匹配规则、页面、将来的识别模块分离。
- 核心搜索和推荐使用已整理数据，不依赖外部 AI 服务或实时搜索。
- 第一版无需业务后端；未来云端识别的密钥只能放服务端。
- 计时器按结束时间校正；后台提醒能力单独验证，不提前承诺。
- 内容覆盖不足时调整收录与组合，禁止通过虚构菜谱补结果。
- 过敏和忌口偏好仅保存在当前浏览器，不上传服务端；本地状态应能容忍空值或损坏存储。

## 8. 验收

- 从添加食材到推荐、详情、备料、分步跟做可在手机尺寸完整操作。
- 必需缺料不能被判为齐全；别名、调料、可选配料和重复食材处理正确。
- 空输入、无匹配、搜索无结果均有可继续操作的提示。
- 食材清单和收藏刷新保留；计时器切换步骤或刷新后的行为明确且正确。
- 每道菜有明确用量、步骤和真实来源；未核实内容不冒充已验证。
- 核心流程不需要调用识别服务。
- 手机布局不横向溢出，主要操作可触达。
- 完成适当的自动化测试、生产构建和浏览器流程验证，修复发现的问题。

## 9. 演示脚本（3–5 分钟）

添加番茄、鸡蛋和已有调料 → 对比齐全与缺料菜谱 → 查看用量、营养与来源 → 进入分步跟做并启动计时器 → 搜索收藏另一道菜 → 刷新验证本地保存。

## 10. 本轮修订与验证重点

用户已确认推荐方案：过敏严格排除，普通忌口可隐藏或提醒。可省调味逐菜判断并说明用途，不能统一忽略全部调料；番茄炒蛋无白胡椒也能做。过敏限制优先于可省规则，但筛选不能替代实际包装与交叉接触检查。

旧版食材、收藏保留；重整配方的 4 道菜清除旧步骤与备料索引，避免误恢复。采用开火前切配/兑汁、阶段计时与可观察熟度；下一阶段候选见 [中文菜谱研究](CHINESE_RECIPE_RESEARCH.md)。单一全局计时器暂不提供后台声音、推送或常亮保证。
