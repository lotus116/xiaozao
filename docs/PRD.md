# 小灶产品需求（整合版）

更新：2026-11-18。离线阶段基线为 1.6.3；饭友圈已按下列范围实现为 1.7.0。自动测试结果见测试记录，真实 Windows／安卓与课堂网络仍待实机验收。本文为产品需求的统一依据；[决策记录](COMMUNITY_PRD.md)保留确认过程，初期范围见 [PRD_INITIAL](PRD_INITIAL.md)。

## 目标

帮助做饭新手从手边食材选择家常菜并完成一餐，支持安卓课堂演示。React + Capacitor 架构保留，安卓 APK 已构建，也可通过网页运行。

流程：添加食材 → 推荐／搜索 → 菜篮 → 备料 → 整页或分步跟做 → 完成后返回保留进度。

## 已实现范围

- 300 道、931 步，涵盖中式、西式及其他地区家常菜，附图片、用量、步骤、教学、来源与编辑边界。
- 手动／批量录入、别名、去重、常用食材及常备调料；未知食材保存并标记，笼统食材手动细分。
- 推荐必须命中已有必需主料，油盐本身不触发弱推荐；必需缺料最多两样，可选项不阻断。“不限食材”是不指定必用主料，而非忽略库存。
- 全库关键词／别名搜索，分类、难度、时间、少配料及收藏筛选；找菜与收藏独立记忆条件。
- 饮食限制优先，直接链接及开做也检查；不能保证包装或交叉接触安全。
- 菜篮增删排序、采购文本、有证据的顺序建议；当前一餐独立于下一餐菜篮。继续跳过已完成菜，恢复待做不打断其他正在做的菜。
- 整页／分步、步骤位置记忆；有依据才显示用量／火力／状态，不编造空缺。备料不强制打勾。
- 单个悬浮计时器支持拖动、长按隐藏、设置恢复、暂停／继续／加时、前台响铃与试听。隐藏不取消计时。
- 可选常亮及失败／释放提示。本地保存食材、偏好、收藏、菜篮、当前进度及计时状态。

## 展示与数据

暖白、番茄红、深棕；A 蒸汽锅标志和矢量文字。顶部找菜／设置，底部四项导航；跟做保留独立工具栏。细节见 [UI_DESIGN](UI_DESIGN.md)。

库存只记种类，不保证用量足够；不自动缩放份数或烹饪时间。当前营养值均为空。300 道尚未逐菜试做，来源作者经验不冒充项目实测。

## 1.6.3 验证与未实现能力

账号、社区、跨设备同步、用户上传／下载菜谱、后端、拍照识别、实时生成菜谱、精确库存扣减、后台／锁屏通知均未实现。安卓打包已完成，iOS 未验收。

## 饭友圈首版（1.7.0 实现范围）

### 目标与边界

2026 年 11 月 20 日课堂展示优先，完成真实联网、双用户、离线跟做与换设备恢复的流程，并保留后续扩展空间。保留 React + Capacitor、原配色、A 标志、现有菜品照片及全部离线功能。

演示：A 注册并发布菜谱 → B 免登录浏览、下载 → B 登录评论 → 加入菜篮并断网跟做 → 在另一设备登录，手动恢复个人配置。

### 已确认功能

| 功能 | 首版要求 |
| --- | --- |
| 账号 | 用户名＋密码注册、登录、退出；免登录浏览与下载，发布、评论、举报、配置备份需要登录；不接短信或第三方登录 |
| 创建菜谱 | 结构化表单和本地草稿；名称、成品图、份数、食材及用量、步骤为必填；步骤用量明确，有依据才填写火力／状态；作者可编辑、删除自己的内容 |
| 社区 | 菜谱列表、搜索、详情，以菜谱为讨论中心；不做独立动态、私信、关注、点赞或社交推荐算法 |
| 讨论与管理 | 评论与单层回复；管理自己的评论；发布即公开，用户可举报，管理员可查看举报并移除内容；管理权限在后端校验 |
| 下载与使用 | 下载特定版本及图片到“我的菜谱”；离线查看、跟做、加入菜篮，符合食材识别及饮食限制条件时参与现有食材推荐；收藏不等于下载 |
| 更新与删除 | 有更新时提示，用户主动更新；当前跟做沿用开始时的版本。作者删除后停止公开展示和新下载，本机已下载副本保留来源、版本并继续可用 |
| 手动配置备份 | 备份／恢复食材、常备调料、常用顺序、收藏和饮食偏好；显示备份时间和覆盖范围，恢复前确认；不自动同步或合并 |

用户菜谱标明作者、来源／原创声明与“用户分享，未经项目核对”。普通用户不必满足内置菜谱的多信源审核标准；内置 300 道继续沿用既有验收标准。

### 数据与失败处理

- 登录本身不上传或覆盖本机配置。主动备份时明确目标账号；恢复时只替换所列配置，不清空本机菜谱、当前一餐或计时器。
- 私有云端备份按账号隔离；退出清除登录凭证和私有云端缓存，取消待执行的账号写入。共享设备上的本机食材等配置仍保留，界面需明确说明；切换账号不能自动把上一账号数据上传给新账号。
- 当前一餐进度、计时器、临时页面状态不跨设备同步。本地草稿按作者账号隔离；退出后隐藏，重新登录原账号可继续。
- 配置备份不包含菜谱图片和下载文件。恢复社区收藏时保留引用；未下载则明确提示需要下载，已删除则显示不可获取，不冒充可离线使用。
- 菜谱使用独立 ID、作者及版本；下载内容完整后才加入本地可用列表。失败保留有效旧版本，重复下载不生成重复副本；发布、评论需防止重复提交。
- 社区食材可按作者原名添加和匹配，也可明确采用已知别名。普通牛肉不会自动顶替牛肉卷。过敏设置继续对未核实的食材给出限制。已下载菜谱可离线删除并从菜篮移除；使用中的跟做、一餐和计时受到保护。
- 离线可保存草稿、使用已下载内容；发布、评论和备份失败时保留输入并提供重试，不显示假成功，不在后台自动补发。

### 页面和交互落实要求

实现前先用文字说明入口、页面布局、点击结果、返回行为、登录拦截、加载／空白／失败状态，再结合页面设计确认。设计图不能作为未经说明的交互依据。

覆盖饭友圈列表／详情、菜谱编辑与草稿、我的菜谱、账号与备份、举报管理。底部第五项为饭友圈，社区内分发现／我的菜谱／账号；[交互约定](COMMUNITY_INTERACTIONS.md)先于实现写入。安卓触点、安全区、返回、键盘和长表单优先；下载、收藏、备份使用不同名称和状态，悬浮计时器及长按隐藏继续保留。

### 部署与展示条件

- 日期：2026-11-20，预计同时使用不超过 10 人。
- 服务电脑：Windows 11 笔记本、16 GB 内存、RTX 3060；本期功能不依赖 GPU。
- 架构方向：现有前端＋Node.js 后端＋SQLite＋图片目录；数据库与图片持久保存，重启不丢数据，提供 Windows 启动说明与数据备份办法。
- 网络：教室 Wi-Fi 可用，可用手机热点备用；手机通过 HTTPS 访问服务，内网穿透作为部署路径，具体工具与地址联调时确定。地址可配置，换服务器不能发送旧服务器凭证。
- 展示前用实际安卓手机完成连通、图片上传、下载和断网检查；电脑接电并关闭自动休眠。网络故障时展示现有离线能力，如实提示社区不可用。

### 验收与交付顺序

1. 先确定页面与交互，完成账号、后端及持久存储；密码安全哈希，接口鉴权，登录／注册限流，图片类型和体积限制，禁止跨账号访问私有数据。
2. 跑通发布 → 另一用户读取 → 下载 → 菜篮 → 离线跟做，包含未知食材、版本更新、作者删除、下载失败与重复操作。
3. 完成评论／回复、举报管理、手动备份恢复；验证换账号不串数据、失败不覆盖有效配置。
4. 运行原功能回归和新增流程测试，再生成 APK；现有 98／409 项结果只属于 1.6.3，不能替代新版验收。
5. 用演示手机和 Windows 服务验证双账号／双设备、服务重启、断网及最多 10 人同时使用的主要操作，记录实际结果。部署与回归验收应在展示前完成，不把全部时间留给功能开发。

以上为同一首版的交付顺序，不代表可自行删减已确认功能。若期限内出现明显风险，先报告具体阻塞和取舍，由用户决定范围。后台／锁屏提醒、拍照识别、自动同步、商业化运营和 iOS 验收均不在本次范围。
