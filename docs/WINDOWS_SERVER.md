# Windows 11 一键部署与课堂演示

目标环境：Windows 11 x64、16 GB 内存，最多约 10 人。无需安装 Node.js、数据库或显卡驱动；GPU 不参与本功能。部署包包含 Node.js 24.21.0、cloudflared 2026.11.1、服务代码及前端页面。

## 从正在运行的 1.7.0 升级

**无需重启 Windows。** 先从 [1.8.0 发布页](https://github.com/lotus116/xiaozao/releases/tag/v1.8.0) 下载 APK 和 Windows x64 ZIP。把 ZIP 解压到新目录，找到里面的 `Start.cmd`。此时旧服务可以继续使用。

1. 告诉同学先保存草稿、暂停发布。关闭旧网络窗口，在旧 `Xiaozao Server` 窗口按 Ctrl+C 并关闭窗口。
2. 在**旧部署目录**双击 `Backup.cmd`，确认 `backups` 中生成了本次 ZIP。保留旧目录。备份中包含用户数据，请私下保管。
3. 打开备份 ZIP，将整个 `server-data` 文件夹和 `server-config.json` 解压到**新目录的 Start.cmd 旁边**。确认能看到 `server-data/kitchen.sqlite`。单独保存旧目录的 `管理员账号.txt`，这个文件不在备份 ZIP 内。
4. 双击**新目录**的 `Start.cmd`。电脑打开 `http://127.0.0.1:8787/api/health`，看到 `ok` 为 `true`、`version` 为 `1.8.0` 即表示新版已运行。用原账号检查一份旧菜谱及其图片。若旧数据缺失，先停止新服务，再检查备份解压位置。
5. 安卓手机直接覆盖安装 APK，保留应用数据。进入“我的 → 账号与备份 → 服务地址”，填入**新网络窗口**给出的完整 HTTPS 地址，点“连接服务”。若提示登录，用原账号登录。

如需切回旧版，先关闭新版两个窗口，再启动原目录的 `Start.cmd`，手机改填它显示的地址。切回时旧目录只含升级前的数据；请另行备份新版运行期间收到的内容。

## 第一次运行

1. 下载 `xiaozao-1.8.0-windows-x64.zip`，**完整解压**到普通文件夹，例如 `D:\xiaozao`，不要在压缩包内直接运行。保留整个目录；不要覆盖旧版数据。
2. 双击 `Start.cmd`。无需管理员运行。首次自动创建数据库和管理员账号，账号保存在同目录的 `管理员账号.txt`，不要分享这个文件。
3. 会出现服务窗口与网络窗口，保持两个窗口打开。网络窗口出现 `https://…trycloudflare.com` 后，复制完整地址。
4. 安卓安装新 APK，进入“我的 → 账号与备份 → 服务地址”，粘贴地址并点“连接服务”。普通同学可以自行注册；管理员使用上述文件的账号登录。
5. 电脑浏览器也可打开该 HTTPS 地址。用于本机检查可打开 `http://127.0.0.1:8787`，并在账号页填同样地址。手机不能用 `127.0.0.1` 连接你的电脑。

## 课堂演示彩排

1. Windows 浏览器打开网络窗口给出的 HTTPS 地址，进入饭友圈，用作者账号发布“照烧牛肉饭”，上传成品照片，材料填“牛肉卷 150 克、熟米饭 1 碗”，补全跟做步骤和本步用量。
2. 安卓手机用另一个账号找到这道菜，点“下载到我的菜谱”，打开离线菜谱并加入菜篮。
3. 手机开启飞行模式并确认 Wi-Fi 已关闭。用一份尚未记录牛肉卷的食材清单，先录入“熟米饭”，再加“牛肉卷”，核对菜篮从缺 1 样变为“必需食材都已记录”。开始跟做，试一次悬浮计时器和长按隐藏。
4. 结束跟做与计时后，在“我的 → 我的菜谱”删除本机下载。恢复联网，确认作者原作还在，可以重新下载、评论。

## 展示当天

- 电脑接电，临时设为不自动睡眠；建议提前半小时启动并在演示手机测试。
- 先试教室 Wi-Fi，连不上时让电脑与手机改用热点。服务使用临时 HTTPS 地址，无需设置路由器端口转发。
- 临时地址每次重启网络连接可能变化，需要重新填入 App；切换地址会退出账号，重新登录后数据仍在。原已下载菜谱继续可用。
- 地址可被知道它的人访问，课堂结束关闭窗口即可停止公开访问。不要把管理员账号与数据备份发给同学。
- 网络服务停止时，App 的内置 300 道和已完整下载的菜谱继续可用；社区页面会显示连接失败，不冒充在线成功。

## 重启、备份和恢复

- 停止：关闭网络窗口，在服务窗口按 Ctrl+C，然后关闭窗口。重启仍双击 `Start.cmd`，不会重新生成管理员密码或删除数据。
- 数据在 `server-data`：SQLite 数据库、图片及可能存在的 WAL 文件；`server-config.json` 保存管理员名等配置。应用代码和数据库分开放置。
- 备份：停止服务后双击 `Backup.cmd`，生成 `backups` 下的日期 ZIP。脚本检测服务仍在运行时会拒绝复制。
- 恢复：停止服务，先另存现有目录，再从备份解压 `server-data` 和 `server-config.json` 到部署根目录，确认替换后再启动。不要仅复制 SQLite 主文件而遗漏尚未合并的 WAL。
- 管理员密码遗失：停止服务后在此目录打开终端，运行 `.\runtime\node.exe server/admin.mjs reset`，生成新密码并撤销旧管理员会话。
- 仅本机排查：双击 `Local-Only.cmd`；它不建立外网连接。不要与已运行的服务同时启动。

## 常见问题

- **8787 端口占用**：通常是重复启动。关闭旧服务窗口，只保留一个服务；本包启动器固定使用 8787，不要单独修改配置端口。
- **网络窗口迟迟没有 HTTPS 地址**：检查联网，换热点后重试；学校网络或运营商可能阻断连接。不要为了展示关闭整个防火墙。
- **App 连接失败**：检查地址是否为本次窗口中的 HTTPS 地址，电脑是否睡眠、窗口是否关闭；在手机浏览器先打开地址检查网络。
- **首次脚本被系统拦截**：核对下载来源与校验值，按 Windows 的提示查看文件属性；不要全局关闭系统保护。
- **不能发布**：需要登录；菜名、图片、份数、食材用量、步骤及本步用量必须完整。失败后去“我的菜谱”找草稿。

## 依赖和验证边界

Node.js 下载与 SHA-256 来自 [Node.js 官方发行目录](https://nodejs.org/dist/v24.21.0/SHASUMS256.txt)。SQLite 使用 [Node 内置接口](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)，无需安装数据库服务。cloudflared 来自 [Cloudflare 官方发布](https://github.com/cloudflare/cloudflared/releases/tag/2026.11.1)。

[Quick Tunnel 官方说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)明确临时地址会变化、无可用性保证，仅适合测试；这里用于短时间课堂展示。它不是永久线上部署。

本包会做依赖校验、压缩包内容检查和同一服务代码的自动测试；Mac 上的验证不等于实际 Windows 双击与课堂网络验收，最终需在这台 Windows 电脑和演示手机运行一次。
